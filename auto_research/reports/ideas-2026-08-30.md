## Top 3 Relevant Papers

### 1. SkillRouter: Skill Routing for LLM Agents at Scale
**arxiv:2603.22455** | March 2026

Multi-skill expert routing where queries are dispatched to N specialist models based on
capability cluster membership. Directly contrasts with MERA's design: MERA routes binary
(small vs. large) using one global skill. SkillRouter's multi-skill approach would break
MERA's routing discriminability — the procedure prefix is constant within each cluster →
zero signal for the TF-IDF router. Citing SkillRouter in §2 LLM Routing for ICLR 2027
pre-empts the obvious reviewer question ("why not multi-skill?") and frames MERA's
single-global-skill choice (CLAUDE.md Decision #1) as a motivated engineering tradeoff.

### 2. Multi-Rollout On-Policy Distillation via Peer Successes and Failures
**arxiv:2605.12652** | May 2026

Introduces a 2×2 peer-signal taxonomy per trace: (A) teacher passes / student fails
[hard positive], (B) both fail [beyond skill], (C) both pass [routine positive],
(D) student passes / teacher fails [anomaly]. MERA's run-both oracle with
`SCALING_FORCE_BOTH=1` produces all four categories for every task. This paper provides
the principled framework to name what MERA already does, strengthening §2b (on-policy
distillation related work) with a 2026 citation that is squarely in MERA's footprint.
The per-cycle breakdown of category sizes also complements EXP-199's teacher-student
gap analysis.

### 3. Routing with Generated Data: Annotation-Free LLM Skill Estimation and Expert Selection
**arxiv:2601.09692** | January 2026

Eliminates the need for oracle routing labels by generating proxy data to estimate model
skill levels. MERA's run-both oracle is the labelled alternative — more accurate but more
expensive. For ICLR 2027 §6 Future Work: annotation-free routing could reduce oracle
call cost while preserving routing accuracy. Provides a natural "cheaper variant of MERA"
framing that reviewers often want to see.
