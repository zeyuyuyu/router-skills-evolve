## Top 3 Relevant Papers Found Today

### 1. arxiv:2608.11095 — "Why Does CLAUDE.md Keep Growing? Catastrophic Remembering in Agentic Coding"

**Relevance: ★★★ — NEW PAPER — DIRECT COMPLEMENT TO EXP-163 — §2 CONTINUAL LEARNING MOTIVATION**

**Key finding** (August 2026, Kushal Chakrabarti): Agentic prompt files (CLAUDE.md, .cursorrules, system prompts) grow WITHOUT BOUND across real repositories. Empirical study of 247,694 instruction lifetimes across 1,867 repositories:
- **+226% growth** over instruction lifetime (more than tripling)
- **+4.9 net instructions per commit** (always growing, never shrinking)
- **Log-hazard -0.032/commit**: the older an instruction is, the LESS likely it is to be deleted
- Root cause: **cheap-append / expensive-delete cost asymmetry**: appending is O(1), but deleting risks correctness regression on all instruction subsets → O(2^|D|) verification cost

The paper names this "catastrophic remembering" — the inverse of catastrophic forgetting — and frames it as a continual learning problem for agentic systems.

**MERA's direct contrast (EXP-163):**

| Property | Catastrophic Remembering (arxiv:2608.11095) | MERA SkillBook (EXP-163) |
|---|---|---|
| Trajectory | +226% growth, unbounded accumulation | **-89% collapse** (1102→118 chars, cycle 0→1) |
| Update criterion | No quality filter — append is free | **Quality-filtered**: update only when small model passes@1=1 |
| Deletion cost | O(2^|D|) — existential risk | **O(1)** — procedure replaced wholesale each cycle |
| Convergence | Divergent (grows forever) | **Convergent** — collapses to near-zero when skill internalized |
| Continual learning label | Catastrophic **remembering** | Catastrophic **forgetting** (of procedure content, not task capability) |

**Camera-ready implications:**
- **§2**: arxiv:2608.11095 is the first paper to empirically characterize prompt bloat as a continual-learning problem. MERA's quality-filtered SkillBook update is the design that prevents catastrophic remembering. The collapse (EXP-163) is the empirical evidence.
- **§8 (Limitations)**: Future work should track the rollback hazard rate (arxiv:2608.11095's -0.032/commit metric) to distinguish catastrophic forgetting (useful content removed prematurely) from successful skill internalization (collapse is desired — model no longer needs the procedure).

**Proposed §2 addition:**
> Recent work characterizes "catastrophic remembering" in agentic systems — the inverse of catastrophic forgetting — whereby agentic prompt files grow without bound (+226% lifetime, +4.9 instructions/commit) due to the O(1)/O(2^|D|) append/delete cost asymmetry (arxiv:2608.11095). MERA's SkillBook design is anti-bloat by construction: the procedure is updated only when the small model achieves pass@1=1 under the current procedure, creating a quality gate that prevents cheap-append accumulation. The empirical result is a controlled collapse (89% shrinkage, EXP-163) — the OPPOSITE of catastrophic remembering — indicating successful skill internalization rather than instruction accumulation.

### 2. arxiv:2608.01678 — "Progressive Agent Skill Generation via Reinforcement Learning" (Skill-α)

**Relevance: ★★★ — PRE-PLANNED (EXP-172) — §2.4 PROCEDURAL SKILL CLUSTER**

**Key finding** (August 2026, CUHK + LIGHTSPEED): Skill-α formulates agent skill generation as a sequential editing process. Each edit is evaluated via a rollback reward: run the task under the original skill and under the edited skill; the reward equals the improvement in downstream execution. This provides a per-edit RL signal without requiring any ground-truth skill labels.

Results: +11.2pp task completion vs. static skill bank; monotonic quality improvement across 3 progressive editing rounds.

### 3. arxiv:2608.01678 + 2608.11095 Combined: Skill Generation and Prompt Bloat as Two Sides of SkillBook Design

**Relevance: ★★ — SYNTHESIS INSIGHT**

The combination of Skill-α (2608.01678) and catastrophic remembering (2608.11095) frames MERA's SkillBook design as a solution to a two-sided problem:
1. **Catastrophic remembering** (2608.11095): naive prompt accumulation grows without bound → need a quality filter
2. **Skill-α** (2608.01678): fine-grained rollback reward prevents premature deletion → need a discriminative signal

MERA's binary pass@1 criterion solves (1) but introduces (2) as a risk: if the criterion is too coarse, it collapses useful content (EXP-163). Future work: combine Skill-α's rollback reward with MERA's cycle-level quality gate to achieve discriminative collapse (remove uninformative procedure tokens) without losing informative ones. This is a concrete §8 future work direction.
