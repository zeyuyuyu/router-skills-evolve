## Top 3 Relevant Papers

### 1. arxiv:2609.01345 — Cheap Verifiers, Large Blind Spots: Measuring the Reliability Cost of Cost-Saving Cascades (Sep 1, 2026)

**Author**: Dushyant Rajput (AltSlate Labs LLP)

**Core idea**: When an inference cascade fine-tunes the student on the verifier's rejections, the verifier's blind spot — the fraction of student wrong answers the verifier erroneously accepts — grows adversarially with student capability: β goes from 0.12 at 0.5B student to 0.55 at 32B student. A frontier verifier drives β to ~0.05 but then escalates on 46% of hard-MATH queries for a 39% true error rate — paying frontier cost on half of all traffic. The paper argues that cost-saving cascades create a reliability trap: the cheaper the verifier, the larger the blind spot; the smaller the blind spot, the less cost is saved.

**MERA intersection**: MERA's verifier is `pytest` — a deterministic execution-based oracle. pytest has zero blind spots by definition: a test either passes or fails, with no ambiguity. This makes MERA's SFT loop structurally immune to the adversarial blind-spot growth that 2609.01345 identifies in LLM-judge cascades. As the student (Qwen3-4B) improves over N cycles, the oracle label distribution shifts (fewer hard tasks), but the verifier never misclassifies a correct answer. This is a key MERA strength not currently articulated in §4 Router Training or §7. Additionally, the "Cheap Verifiers" framing clarifies WHY MERA's run-both oracle is necessary: running the large model on every task avoids the blind-spot trap of using only the cheap-model output as the learning signal.

**Paper impact**: §4.1 Trace Collection and/or §7 should note that MERA's execution-based reward (pytest) achieves β≈0 by construction, avoiding the reliability trap. One sentence in §4.1 and a bib entry `cheapverifiers2026`.

### 2. arxiv:2609.11446 — Calibration-Aware Uncertainty Cascades for Efficient Heterogeneous Model Collaboration (Sep 10, 2026)

**Authors**: Yilin Zhang, Han Jiang, Cai Xu, Ying Liu, Wei Zhao

**Core idea**: CAUC independently calibrates each model's confidence using post-hoc temperature scaling on validation data, establishing a common reliability scale. Deployment policy (accept early / invoke strong / combine outputs) is selected using calibrated confidence thresholds, decoupled from the model pool and operating budget. Evaluated on 6 LLM benchmarks + 3 image classification datasets.

**MERA intersection**: MERA's router is a logistic regression trained on oracle labels from paired runs (raw prompt features, no calibration). CAUC provides the calibration-based contrast: where CAUC decouples calibration from the model pool, MERA's oracle-label training implicitly calibrates routing confidence by observing actual pass/fail outcomes (the ground-truth calibration). The key MERA advantage over CAUC: MERA's router re-calibrates each cycle as the student's capability distribution shifts — CAUC requires re-running the calibration procedure on fresh validation data each time a model is updated. MERA's cycle-wise routing update is an online, end-to-end analog of CAUC's offline post-hoc calibration. Tagged in the Sep 12 hotspot but not yet acted on (queue cap hit that run).

**Paper impact**: §2 LLM Routing — one sentence distinguishing MERA's oracle-trained router (end-to-end, cycle-wise recalibration) from post-hoc calibration approaches (CAUC, UCCI arxiv:2605.18796). Add bib entry `cauc2026`.

### 3. arxiv:2509.22984 — From Deferral to Learning: Online In-Context Knowledge Distillation for LLM Cascades (Sep 2025)

**Authors**: Yu Wu, Shuo Wu, Ye Tao, Yansong Li, Anand D. Sarwate

**Core idea**: Inter-Cascade transforms the strong model from a temporary helper into a persistent teacher. When the weak model defers a query to the strong model, the strong model's strategy is cached and injected as an in-context example for future similar queries via similarity retrieval. The weak model "learns" during inference without parameter updates.

**MERA intersection**: Inter-Cascade represents the zero-parameter-update end of the knowledge transfer spectrum. MERA is at the opposite end: SFT bakes the strong model's solutions into weights (generalizes to structurally new prompts) and GRPO reinforces correct behaviors with on-policy rollouts. Inter-Cascade requires O(N) cached traces + retrieval overhead at every inference call; MERA's fixed-size LoRA adapter adds zero inference latency. This contrast strengthens MERA's §2 positioning. However, Inter-Cascade is a background cite candidate, not a threat (Sep 2025, well-understood; no conflict with MERA's methodology).

**→ Background cite candidate (incorporated into EXP-214 or EXP-215 as bib entry `intercascade2025`)**
