## Top 3 Relevant Papers

### 1. arxiv:2609.16008 — Co-Skill: A Collaborative Communication Framework for Skill Evolution (Sep 17, 2026) ⚠️ HIGH PRIORITY

**Authors**: (Undisclosed in search results, from search result context at arxiv.org)

**Core idea**: Co-Skill addresses the cloud-edge hybrid skill evolution problem: a cloud LLM (large, strong) analyzes execution traces and generates a skill context (prefix-merged trajectory trie + progressive skill tree); an edge SLM (small, locally deployed) receives the synthesized skill prefix and absorbs it via RL. The Collaborative Communication Framework (CCF) enables the cloud to perceive the edge's execution capability and the edge to understand the cloud's analysis intent, avoiding "blind communication" that prior methods (e.g., SkillRL) suffer from. Results: 25.8%–76.4% task success rate improvement and 15.6%–41.9% token reduction over SotA hybrid methods on ALFWorld and WebShop.

**MERA intersection**: Co-Skill and MERA share the same structural paradigm: a large cloud model generates skill-level guidance from execution traces → a small edge model uses this guidance on future tasks. This is MERA's SkillBook pipeline in a different domain (agent navigation/shopping vs. code generation). Key MERA differentiators:

1. **Skill representation**: Co-Skill uses a *per-trajectory trie* (structured tree of execution paths). MERA's SkillBook distills a *single global procedural paragraph* (`"coding"` skill, CLAUDE.md decision 1). MERA's global skill is intentionally coarse — it trades per-task granularity for router discriminability and avoids per-cluster interference (CLAUDE.md §design decision 1).
2. **Internalization mechanism**: Co-Skill uses in-context prefix injection (the skill tree is prepended at inference time — zero parameter update). MERA bakes skills into LoRA weights via SFT+GRPO (permanent internalization, zero inference overhead after training).
3. **Router**: Co-Skill has no separate routing component — it always invokes the cloud LLM for skill synthesis. MERA co-trains an explicit logistic regression router that learns to route WITHOUT cloud invocation for easy tasks (93.04% routing accuracy at 27.56% cost).
4. **Oracle**: Co-Skill uses agent task success/failure as reward signal. MERA uses `pytest` execution — a deterministic oracle with β=0 blind-spot rate (cf. EXP-214 / arxiv:2609.01345).
5. **Domain**: Co-Skill targets agentic navigation (ALFWorld) and shopping (WebShop). MERA targets code generation (HumanEval 164) — structurally different: code has a formal verifier, agent tasks have stochastic environment dynamics.

**Paper impact**: Co-Skill was revised on Sep 17, 2026 — 14 days before ICLR 2027 deadline. It is not cited in MERA's §2 (paper.md last updated before Sep 17). An ICLR reviewer in the agentic systems space will find Co-Skill and may see MERA's SkillBook contribution as reduced novelty unless §2 explicitly differentiates. The concurrent-work framing is appropriate: both papers appear in the Aug–Sep 2026 window. Adding 1–2 sentences to §2 (Skill Distillation subsection, after SkillForge bib entry) costs 0 GPU hours and closes the reviewer risk.

### 2. arxiv:2609.11682 — COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization (Sep 10, 2026)

**Authors**: Pingchen Lu, Xiangyi Wang, Xiang Li, Jie Mao, Zikun Qu, Junfeng Luo, Yao Shu, Bryan Kian Hsiang Low, Zhongxiang Dai

**Core idea**: COBRA-Skills formulates skill optimization as a budgeted sequential optimization problem over a dynamically evolving skill candidate space. It couples contextual-bandit-guided prioritization (selectively allocate evaluation budget to the most promising or informative skill candidates) with evidence-grounded skill evolution (refine the skill population from execution feedback). Evaluated across 6 heterogeneous agent benchmarks and 3 target LLMs; consistently achieves the strongest average performance.

**MERA intersection**: COBRA-Skills addresses skill *selection and evaluation efficiency* — which skills to test next given a fixed evaluation budget. MERA's skill evolution pipeline runs a different optimization: for each cycle, the SkillBook is updated from the full trace set (not via bandit-guided sampling). COBRA-Skills is a complementary contribution in the skill optimization space: where COBRA-Skills answers "which skill candidates to evaluate?", MERA answers "how do SFT+GRPO internalize a skill into the model once selected?". The two systems are orthogonal in mechanism. COBRA-Skills is a background cite candidate for §2 Self-Evolving Agentic Systems (the bandit-guided selection complements MERA's oracle-label router). Lower ICLR risk than Co-Skill (different mechanism, no direct overlap), but present in the same Sept 2026 window.

### 3. arxiv:2609.20455 — SkillAA: Attribution-Guided Skill-Graph Updating with Targeted Validation and Rollback (Sep 2026)

**Core idea**: Maintains a skill graph where each node is a skill procedure; edges capture dependency. Attribution analysis identifies which skills contributed to failures; a rollback mechanism reverts unsafe skill updates. Validated on agent benchmarks.

**MERA intersection**: SkillAA targets multi-skill dependency management with rollback — MERA uses a single global skill (CLAUDE.md decision 1) precisely to avoid inter-skill interference, and has no rollback mechanism (its "rollback" is the checkpoint priority chain: GRPO > SFT > base). SkillAA validates the concern MERA's §2 should acknowledge: per-skill granularity with attribution rollback is the "full" design MERA deliberately reduces to a single-bucket approximation. A reviewer might ask "why single skill?" — SkillAA is the example of what the multi-skill path looks like, and MERA's §2 can cite it to justify the simplification.

**→ Background cite candidate — scope included in EXP-220 if time permits, else future queue**
