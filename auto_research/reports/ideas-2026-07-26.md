## Top 3 Relevant Papers

### 1. arxiv:2607.21273 — The Dark Room in the Reward Channel: Dense Prediction Rewards Collapse GRPO-Trained LLM Agents — and What Actually Works
**Wang, July 23 2026**

This paper formalizes the zero-variance GRPO collapse we empirically identified at ACR=52.4%
as the **"dark room" pathology**: when all K rollouts in a group receive the same reward,
GRPO's z-normalization produces 0/0 advantages — the policy is trapped in a zero-gradient
absorbing state, "standing still in the dark." Dense per-step prediction rewards actively
make this worse: bounded reward values produce identical z-scores, so the normalized
advantage is **scale-invariant** — increasing the shaping coefficient does not help.

Key results (Qwen3-1.7B/4B/8B on ALFWorld):
- Dense prediction reward: **every run → 0% task success** (absorbing state)
- Dr. GRPO (remove σ): same dense reward → **baseline parity** (pathology eliminated)
- Sparse terminal binary reward + standard GRPO: **works correctly** from the start

**Why it matters for us:**
1. **Terminology:** "Dark room" is more vivid and citable than "zero-variance collapse."
   Adopting this term strengthens §5.4's theoretical narrative for AAAI reviewers.
2. **Tau2 diagnostic gap:** We have ACR=52.4% for HumanEval, but we have NEVER measured
   the dark-room fraction for tau2 multi-turn GRPO groups. The tau2 oscillation
   (89.19%→70.27%→72.97%) is our paper's most striking failure mode — linking it to the
   dark-room mechanism via a fast diagnostic (<1h) is high AAAI value.
3. **"What Actually Works" confirms sparse binary reward is safe:** Our HumanEval and
   tau2 tasks already use sparse terminal binary reward (pass/fail). This means the
   collapse is **not** the dense-reward dark room — it's the homogeneous-reward dark room
   (all 8 rollouts fail identically). Dr. GRPO (EXP-120) is the correct fix.

→ Queued as **EXP-134** (forgetting_eval diagnostic for tau2 dark-room fraction).

### 2. arxiv:2607.16244 — CIGPO: Contextual Information-Gain Policy Optimization for Multi-Turn Evidence-Reading LLM Agents
**Dou (Harbin Institute of Technology), July 2026**

CIGPO addresses multi-turn GRPO collapse: when intermediate turns produce no direct reward,
all K trajectories eventually receive identical terminal rewards → zero advantage → dark room.
CIGPO injects per-turn **contextual information gain** (reduction in reference model's
uncertainty at each evidence-reading turn) as an intermediate reward signal.

For **code repair** (our HumanEval DAPO G=8 turns), the natural CIGPO analogue is
**test-coverage information gain**:

```
IG_t = pass_rate(turn_t_code) - pass_rate(turn_{t-1}_code)
```

Each repair turn gets credit proportional to how many additional tests it clears, even when
the terminal reward=0. This breaks the ACR dark-room lock for partially-progressing trajectories.

Key results: +12pp HotpotQA F1 (Qwen2.5-3B-Instruct), stable training (no format collapse).
Original GRPO baseline collapses to 100% format violations within 50 steps.

**Why it matters:**
- Addresses Problem B (our 47.6% non-ACR groups carry all gradient) AND partially addresses
  Problem A (ACR groups where all trajectories fail but some make intermediate progress)
- Orthogonal to SCCA (EXP-131, token-level), Dr. GRPO (EXP-120, σ removal), AVSPO (EXP-122,
  virtual injection) — the only turn-level coverage-gain approach in the queue
- Implementation is ~30 lines in grpo_train_simple.py

→ Queued as **EXP-135** (CIGPO-Code for HumanEval multi-turn repair).

### 3. arxiv:2605.22057 — FlyRoute: Self-Evolving Agent Profiling via Data Flywheel for Adaptive Task Routing
**Li, Zhou, Wu (Huawei), updated July 23 2026**

FlyRoute builds a self-evolving capability evidence store from real traffic using a data
flywheel: dispatch candidates → quality-gate successful pairs → distill into capability
descriptions → inject as context for LLM-based routing. Cold-start (5 seeds): **78.04%**
→ full traffic (7,211 queries): **89.83%** on enterprise dev-support benchmark.

**Why it matters for us:**
Our BERT router reaches 93.04% routing accuracy — better than FlyRoute's peak on its
benchmark. FlyRoute's main contribution is **cold-start warm-up via evidence distillation**,
which our SkillBook already approximates via capability statistics. The key difference is
FlyRoute's **targeted exploration policy** (profile uncertainty × BM25 relevance × lexical
novelty), which intelligently selects which queries to dispatch for evidence collection.
If implemented as a SkillBook warm-start, this could reduce the number of cycles needed
before the router converges. *Not queued today* (marginal value vs. queue backlog and
AAAI deadline proximity; HyDRA router EXP-129 already addresses router architecture).

### EXP-135: CIGPO-Code — Per-Turn Test-Coverage Credit for HumanEval Multi-Turn GRPO
**ID:** `exp_2026_07_26_002_cigpo_code_perturn_coverage_humaneval`  
**Priority:** 7 · **Kind:** `grpo_continual` · **GPU hours:** ~3.5h

**Addresses:** Problem A (ACR groups with partial progress) + Problem B (non-ACR gradient quality)  
**Arxiv:** 2607.16244 (July 2026)

**What changes (~30 lines in grpo_train_simple.py):**
1. For each multi-turn repair trajectory, run pytest at each turn to get `pass_rate_t`
2. Compute `IG_t = max(0, pass_rate_t - pass_rate_{t-1})` for each turn t
3. Add per-turn CIGPO loss: `L_cigpo = -CIGPO_ALPHA * IG_t_norm * log_prob(turn_t_tokens)`
4. Combined: `L = L_GRPO_terminal + sum(L_cigpo_t)` across all turns with IG_t ≥ 0.05
5. Log per-turn IG distribution and "tasks graduated from ACR" metric

**Env vars:** `CIGPO_CODE_ENABLED=1`, `CIGPO_ALPHA=0.3`, `CIGPO_MIN_IG=0.05`,
`CIGPO_MAX_TURNS_EVAL=3` (limit eval overhead)

**Expected outcome:** Full arm 92.68% → ≥93.5%; non-ACR gradient quality improves;
some ACR groups break out of dark room if intermediate turns show IG > 0.
