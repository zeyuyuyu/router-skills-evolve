### 1. arxiv:2605.28791 — "SGSD: Skill-Gated Self-Distillation for Continual LLM Reinforcement Learning"

**Relevance: ★★★ — MULTI-SKILL DISTILLATION COUNTERPOINT TO OUR SINGLE-SKILL DESIGN**

**Key finding** (May 2026): SGSD maintains a structured skill bank from experience traces. Each skill bucket triggers a different distillation policy: high-confidence skills (pass rate > 0.8) receive behavior-cloning distillation to prevent forgetting; emerging skills (0.2–0.8 pass rate) receive on-policy RL; failing skills (< 0.2) trigger teacher injection. The skill bank is maintained per-task-cluster (K-means on task embeddings). Result: +6.2pp over vanilla GRPO on sequential coding tasks, attributed to preventing catastrophic forgetting of high-confidence skills while focusing RL budget on emerging ones.

**Contrast with our design**: Our CLAUDE.md §Design Decision 1 explicitly enforces ONE global skill ("coding") — `extract_signature()` always returns "coding". This was a deliberate architectural choice to avoid the routing/ablation complexity of multi-skill management. 2605.28791 provides the theoretical counterpoint: within a homogeneous domain like HumanEval, task-level pass rate stratification (their "confidence-based skill bucket" assignment) can identify sub-skill clusters even without semantic clustering. Our EXP-152 audits this offline: cluster the 82 HumanEval tasks by cycle-0 pass@1 decile (easy/medium/hard) and check whether the arms' relative advantage concentrates in the medium bucket (as SGSD §3.2 predicts).

**Paper uses** (2 locations):
1. **§2 Related Work** (new subsection paragraph): "SGSD (arxiv:2605.28791) maintains a multi-bucket skill bank from experience traces, applying different distillation policies per confidence tier. Our design deliberately uses a single global skill to avoid multi-skill ablation complexity (§3.1); EXP-152 provides a post-hoc feasibility audit of whether task-complexity stratification within our single-skill framework would benefit from SGSD-style tiering."
2. **§8 Future Work** (existing paragraph on multi-skill extension): "A natural extension is to adopt SGSD's confidence-tiered distillation within the router-skills co-training loop: easy tasks (pass@1 > 0.8) could receive direct behavior-cloning, while medium-difficulty tasks (0.2–0.8) receive the current procedure-augmented RL. Our single-global-skill design (CLAUDE.md §1) was an explicit simplification; SGSD-style tiering would replace it."

### 2. arxiv:2607.25659 — "CoRT: Counterfactual Replay for Token-Level Rubric-Guided Policy Optimization"

**Relevance: ★★★ — TOKEN-LEVEL CREDIT ASSIGNMENT VIA TEACHER LOG-PROB CONTRAST**

**Key finding** (Jul 28 2026): Standard GRPO broadcasts the response-level advantage uniformly to every token, including boilerplate (`def`, `return`, whitespace). CoRT replaces uniform token weighting with a teacher-student log-likelihood contrast: for each token position in a student rollout, compute `w_t = clamp(log(pi_teacher(t|ctx) / pi_student(t|ctx)), -5, 5)`; multiply the GRPO advantage by `softmax(w_t)` to concentrate the gradient signal on semantically important tokens (variable assignments, logic branches). No auxiliary reward model; no architecture change; single teacher forward pass per rollout. Mean +4.4pp across code and math instruction-tuned models.

**Feasibility for our pipeline**: Our `traces.jsonl` already contains GPT-5.5 completions for every task (via SCALING_FORCE_BOTH=1). Computing the CoRT weight distribution requires:
1. A teacher forward pass over student rollout tokens using the GPT-5.5 log-probabilities
2. Categorizing tokens by syntactic type (function keyword, return statement, variable name, operator, whitespace)

Note: GPT-5.5 does not expose per-token log-probabilities via the public API. HOWEVER, we can approximate the teacher distribution using our own fine-tuned small model as a surrogate (cycle-3 `llm_adapter/checkpoint-best`) since after 4 cycles of SFT distillation, the small model's distribution should approximate the teacher on training tasks. This makes EXP-153 a local-only computation: no API call, no GPU (just logprob read from existing model checkpoints via a single frozen forward pass).

**Paper use** (§2 + §7):
- §2: "CoRT (arxiv:2607.25659) redistributes per-token GRPO advantage via a teacher-student log-likelihood contrast, gaining +4.4pp by focusing gradients on semantically critical tokens. EXP-153 audits the feasibility of this mechanism on our 4-cycle traces; the surrogate teacher is the cycle-3 fine-tuned checkpoint (log-prob computation only, no training)."
- §7 "Token-Level Gradient Credit" paragraph (new): "A complementary improvement is token-level advantage redistribution (CoRT, arxiv:2607.25659). EXP-153 suggests [token distribution result from experiment] — sufficient signal separation to motivate a post-AAAI CoRT integration."

### 3. arxiv:2605.30896 — "The Flat Basin Theorem: Why All-Fail Groups are Irrerecoverable Under Policy Gradient"

**Relevance: ★★★ — FORMAL BACKBONE FOR THE ENTIRE DARK ROOM SERIES**

**Key finding** (May 2026): Formal proof that under binary (pass/fail) rewards and standard policy gradient with any non-negative step size, if all K rollouts in a group fail (reward = 0), the parameter update is identically zero regardless of the policy distribution. This is the "flat basin": the policy is at a saddle point from which no first-order gradient step can escape without external perturbation. The result extends to GRPO's std-normalization variant and holds for any reward in {0, 1}. The paper proposes three escape mechanisms: (a) adding a small ε baseline reward (equivalent to std-norm removal), (b) importance-weighted sampling from a reference policy (equivalent to OC-GRPO), (c) SFT on teacher demonstrations (equivalent to RSTG).

**Status**: This paper provides the STRONGEST theoretical foundation for our entire dark room series (EXP-135/147/148/150). All three mechanisms (a), (b), (c) have direct analogs in our queued experiments. More importantly, the theorem applies directly to HumanEval's binary scoring: our reward function is exactly in {0, 1}.

**Paper additions** (2 locations):
1. **§5.3 opening theorem citation**: "The Flat Basin Theorem (arxiv:2605.30896) formally proves that under binary rewards, confirmed all-fail GRPO groups produce identically zero gradient regardless of policy distribution — the optimizer is basin-trapped. Across our 4 cycles, 10-13 tasks per cycle satisfy the all-fail condition (Figure 3); the effective gradient utilization rate is [EXP-149 result]% (Table 10)."
2. **§2 Continual RL subsection**: Add flat basin theorem to the theory paragraph after the zero-variance citations.

**Rationale**: arxiv:2605.28791 (SGSD, May 2026) demonstrates that task complexity stratification within a single skill domain reveals differential arm advantages: GRPO (their "RL" arm) outperforms distillation on medium-difficulty tasks (pass@1 ∈ [0.2, 0.8]) but underperforms on easy tasks (pass@1 > 0.8, where forgetting dominates) and hard tasks (pass@1 < 0.2, where zero-variance collapses). Our design uses a single global "coding" skill (CLAUDE.md §1), deliberately avoiding multi-skill complexity. EXP-152 audits this design decision post-hoc: partition the 82 HumanEval tasks into 3 difficulty tiers by cycle-0 cold pass rate, then compute per-tier pass@1 for each of the 4 ablation arms across cycles. Expected finding: Full arm advantage concentrates in medium-difficulty tier (consistent with SGSD §3.2), router arm advantage concentrates in hard-tier (routing protects small model from zero-variance collapse), skills arm underperforms on easy-tier (forgetting of already-solved tasks). This finding directly motivates SGSD-style tiering as §8 Future Work while also justifying the current single-skill design for the current evaluation setup.

**Implementation sketch**:
```python

from pathlib import Path

# Load cycle-0 cold pass rates (from e2e_ablation_summary.json large arm, cycle 0)
cy0 = json.load(open("results/e2e_4cyc_gpt55/cycle_0/e2e_ablation_summary.json"))
large_c0 = cy0['large']['per_task']  # {task_id: {"pass_at_1": float}}

# Partition into 3 tiers by cycle-0 large arm pass@1
tiers = {'easy': [], 'medium': [], 'hard': []}
for t, r in large_c0.items():
    p = r['pass_at_1']
    tiers['easy' if p > 0.8 else ('hard' if p < 0.2 else 'medium')].append(t)

# Per-tier arm pass@1 across cycles
arms = ['large', 'skills', 'router', 'full']
for tier_name, tier_ids in tiers.items():
    for arm in arms:
        per_cycle = []
        for cycle in range(4):
            cy = json.load(open(f"results/e2e_4cyc_gpt55/cycle_{cycle}/e2e_ablation_summary.json"))
            per_cycle.append(np.mean([cy[arm]['per_task'].get(t, {}).get('pass_at_1', 0.0) for t in tier_ids]))
        print(f"Tier={tier_name} Arm={arm}: {per_cycle}")
```
