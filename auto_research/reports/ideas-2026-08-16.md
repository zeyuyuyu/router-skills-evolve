### 1. arxiv:2608.05156 — "Scaffold-Mediated Post-Training: Co-Evolving Model Parameters and Procedural Scaffold Graphs"

**Relevance: ★★★ — CLOSEST STRUCTURAL CONCURRENT ANALOG TO MERA — CAMERA-READY CRITICAL**

**Key finding** (August 2026, Alibaba Group + Tsinghua University): Proposes "Scaffold-Mediated Post-Training," a framework that organizes procedural scaffolds into an evolvable graph structure that co-evolves with model parameters through three phases: (1) **discovery** — scaffold nodes are initialized from teacher demonstrations (≡ MERA cycle-0 SkillBook seeding from GPT-5.5); (2) **distillation** — each scaffold node is trained into the model via SFT+RL (≡ MERA SFT+GRPO phases); (3) **dynamic recompilation** — scaffold graph edges are reweighted based on model performance, pruning ineffective procedures (≡ MERA's per-cycle SkillBook evolution from successful small-model traces). Results on FeatureBench: automatically discovered skills improve pass rate by 8.1pp; after progressive distillation, model achieves 27.7% pass rate without any external scaffold (distillation retention rate 85.2%).

**MERA vs. Scaffold-Mediated Post-Training — key differentiators:**

| Dimension | MERA | Scaffold-Mediated (2608.05156) |
|---|---|---|
| Procedural skill source | GPT-5.5 teacher traces (cycle 0) + small model successes (cycles 1-3) | Automated scaffold discovery from teacher demonstrations |
| Skill structure | SkillBook: single global "coding" skill (flat key-value) | Scaffold graph: nodes = procedures, edges = task-dependency weights |
| Model parameter update | SFT (phase 3a) + GRPO (phase 3b) | SFT + RL (aligned objectives) |
| Routing component | **Yes — explicit logistic regression router (Phase 4) for small/large dispatch** | **No routing — single-model post-training** |
| Co-evolution across cycles | Yes (3-component: LLM + SkillBook + Router) | Yes (2-component: model params + scaffold graph) |
| Inference-time scaffold | Yes (cycle 0 only; collapses cycles 1-3, EXP-163) | Eliminated after distillation (retention rate 85.2%) |
| Task domain | Code generation (HumanEval, MBPP) | Multi-step reasoning (FeatureBench) |
| Submitted | — | August 2026 |

**Why this is camera-ready critical**: The paper's most distinctive claim is 3-component co-evolution (LLM + SkillBook + Router). If a reviewer finds 2608.05156 and MERA's §2 does not address it, the question "how does MERA differ from Scaffold-Mediated Post-Training?" becomes a major reviewer weakness. The key differentiator is the **explicit learnable router** for small/large LLM dispatch — Scaffold-Mediated trains a single model, while MERA's routing component is absent from all concurrent work including ADRS, OCSD, DA-GRPO, CoPES, and Scaffold-Mediated.

**Proposed §2 addition (camera-ready):**

### 2. arxiv:2608.06867 — "LLMRouter: Unified Infrastructure for Developing, Evaluating, and Deploying LLM Routers"

**Relevance: ★★★ — ROUTING TAXONOMY CONCURRENT — §2 ROUTER SUBSECTION CRITICAL**

**Key finding** (August 7, 2026, UIUC + Maryland + NTU + Purdue + UIC): Proposes LLMRouter, a unified infrastructure that frames LLM routing as a sequential decision process with five components: (1) context encoders, (2) model encoders, (3) scoring functions, (4) decision rules, (5) learning signals. Introduces **xRouteBench** (cross-task routing benchmark) and an open-source library with 16+ representative routers spanning classification-based, regression-based, and LLM-judge-based designs. Key finding: learned routers outperform the strongest fixed-model baseline by **14.6% relatively** on xRouteBench.

**MERA's router within the LLMRouter taxonomy:**
- Context encoder: bag-of-words TF-IDF over raw problem text (Phase 3 training inputs)
- Model encoder: none (binary label: small model pass/fail at current cycle)
- Scoring function: logistic regression sigmoid
- Decision rule: fixed threshold τ = 0.5 (uncalibrated — see EXP-154 UCCI audit)
- Learning signal: cross-entropy on GPT-5.5 trace labels + small model eval outcomes

**Key differentiators of MERA's router from LLMRouter's taxonomy:**
1. **Co-evolution**: MERA's router re-trains each cycle on updated (small model checkpoint, large model trace) labels — it's not static but dynamically tracks the small model's improving capability. LLMRouter's benchmark evaluates static router policies.
2. **Skill-conditioned routing**: MERA's routing decision is implicitly conditioned on the SkillBook procedure quality (cycle 0 routing is informed by cycle-0 skill; cycle 3 routing by the collapsed cycle-3 skill). No LLMRouter router co-evolves with a skill bank.
3. **xRouteBench baseline**: LLMRouter finds its best learned router achieves 14.6% over fixed-model. MERA's router at cycle 3 achieves 92.68% routing accuracy at 27.56% escalation cost — a favorable comparison point for §2.

**Why this is camera-ready critical**: LLMRouter provides the reference taxonomy for §2's "Router" subsection. Reviewers familiar with LLMRouter will immediately ask "how does MERA's router map onto this taxonomy?" without a citation. Citing LLMRouter + providing the mapping positions MERA's contribution as a *co-evolutionary* router variant that extends the LLMRouter framework with skill-conditioned, cycle-aware routing.
