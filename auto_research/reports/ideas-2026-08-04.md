## Top 3 Relevant Papers Found Today

### 1. arxiv:2606.21090 — "Self-Improvement Can Self-Regress: The Rise-and-Collapse Failure Mode of LLM Self-Training"

**Relevance: ★★★ — HIGHEST PRIORITY TODAY**

**Key finding** (Jun 17 2026): In controlled multi-seed experiments with Qwen-2.5-3B/7B on
competitive-programming tasks with binary CodeGrader reward across 10 sequential 20-step
campaigns, pass@1 shows a **robust rise-then-collapse** pattern within every campaign: it peaks
within tens of gradient steps and then falls back, sometimes near zero. This is NOT cross-task
catastrophic forgetting — it is within-task over-optimization on a fixed task distribution.
KL-constraint and EWC-style approaches do not prevent it. Mechanism: easy-reward tasks are
quickly solved early in training, removing their gradient contribution; the residual gradient
from harder tasks then over-fits the model to their surface patterns, degrading performance on
previously-mastered easy tasks.

**Direct application**: Our cycle-3 shows the strongest within-campaign advantage decline
(0.959 → 0.683, -28% from first to middle third). The `all_pass` count grew from 26 (cycle-2)
to 33 (cycle-3), meaning 7 additional tasks graduated to "always solved" — their gradient
contribution disappears mid-campaign, reducing the effective training signal for the remaining
49 tasks. The paper's framework predicts that these 49 residual-gradient tasks are at
over-optimization risk in cycle-3, explaining the observed cycle-3 plateau
(75.61% skills arm — no improvement vs cycle-2's 73.17% after router correction).

**Paper impact**: §5.3 gains a "within-campaign dynamics" paragraph grounded in arxiv:2606.21090.
Figure 3 (mean|adv| trajectory) provides visual evidence. EXP-146 (queued today) formalizes
this with scipy curve-fitting and a within-campaign over-optimization metric.

**Distinction from EXP-132**: EXP-132 (priority=9, blocked on A800) is a GPU experiment that
re-runs cycle-3 GRPO with checkpoint-at-peak capability (stop at the rise peak, before collapse).
EXP-146 is an offline-only audit that characterizes the collapse from existing logs without
new training. Both are needed: EXP-146 provides the narrative; EXP-132 provides the fix.

### 2. arxiv:2607.26457 — "DHRCL: Training Code LLMs with Dense Hierarchical Rewards and Curriculum Learning"

**Relevance: ★★★ — ROOT-CAUSE FIX FOR DARK ROOM EFFECT**

**Key finding** (Jul 29 2026, submitted): DHRCL decomposes GRPO feedback into a 3-tier
hierarchy — syntax validation (reward_syntax=0.1), execution success (reward_exec=0.3), and
unit-test pass rate (reward_pass=1.0) — and organizes training with a 3-stage Syntax→Execution→Pass
curriculum where stage transitions are triggered by rolling validation trends rather than
manually-specified thresholds. Stage-aware token credit redistribution follows a
consolidation-to-refinement principle (uniform token credit during syntax stage; task-weighted
credit during pass stage). Outperforms GRPO, GRPO-PassRate, AceCoder, and VeRPO on HumanEval,
HumanEval+, BigCodeBench-Full/Hard, LiveCodeBench V6, and CodeElo.

**Direct application**: Our Dark Room quantification shows 10-13 all_fail tasks per cycle
(12-16% of training tasks) receive zero gradient under binary rewards. With DHRCL's 3-tier
reward:
- A rollout that produces syntactically valid Python gets reward=0.1 (vs 0.0)
- A rollout that runs without import/runtime error gets reward=0.3 (vs 0.0)
- A rollout that passes all tests gets reward=1.0

For all-fail Dark Room tasks, even rollouts that only compile now get a small positive signal.
If K=8 rollouts on a hard task split between syntax_fail (reward=0.0) and execution_fail
(reward=0.3), the group now has nonzero variance → nonzero advantage → nonzero gradient.
This recovers gradient on ~21% of the zero-advantage Dark Room group (the `all_fail` portion).

**Contrast with EXP-135** (no-std-norm GRPO, priority=8, blocked on A800):
- EXP-135 is a **symptom fix**: normalize advantages even when group std≈0 (prevents the
  zero-gradient outcome per Proposition 1). Does not change the reward signal.
- EXP-147 (today) is a **root-cause fix**: make rewards denser so hard tasks naturally
  produce nonzero group variance. More principled, but requires modifying the reward function.

Both should be tested as a 2×2 ablation: {binary_reward, 3-tier_reward} × {std_norm, no_std_norm}.

**Paper impact**: Adds a 2×2 Dark Room ablation to Table 9 (or a new Table 10 "Dark Room fixes").
If 3-tier reward reduces all_fail from 10-13 to <5/cycle while maintaining HumanEval pass@1,
this is the strongest Dark Room fix finding and a direct contribution of DHRCL to our system.

### EXP-147: DHRCL 3-Tier Hierarchical Reward for HumanEval GRPO *(~1.5h GPU)*

| Field | Value |
|---|---|
| ID | `exp_2026_08_04_002_dhrcl_3tier_hierarchical_reward_grpo_humaneval_dark_room` |
| Kind | `grpo_continual` |
| Priority | 7 |
| GPU | ~1.5h |
| arxiv | 2607.26457 |
| AAAI priority | HIGH — root-cause Dark Room fix; completes 2×2 ablation with EXP-135; adds Table 10 |
| Dependency | Run after EXP-135 (priority=8) to enable 2×2 comparison |

**Rationale**: Offline analysis shows 10-13 all_fail tasks per cycle receive zero GRPO gradient
under binary rewards (binary Dark Room). arxiv:2607.26457 (DHRCL, Jul 29 2026) proposes a
3-tier hierarchical reward (syntax_ok=0.1, execution_ok=0.3, all_tests_pass=1.0) that provides
non-zero signal to rollouts that at least compile or run. For our 10-13 all_fail Dark Room tasks,
some rollouts will reach syntax_ok or execution_ok tiers even if they don't pass all tests,
recovering the zero-variance group that currently blocks GRPO learning on these tasks. This is a
root-cause fix (dense rewards) vs EXP-135's symptom fix (no-std-norm normalization). The two
experiments form a 2×2 ablation (reward_density × normalization_strategy), cleanly isolating
which Dark Room mitigation strategy drives gains.

**Implementation**: Modify `grpo_train_simple.py`'s reward computation:
```python
def tiered_reward(code, task):
    try:
        ast.parse(code)     # syntax check
        syntax_ok = True
    except SyntaxError:
        return 0.0
    try:
        subprocess.run(code, timeout=5)  # execution check
        exec_ok = True
    except:
        return 0.1
    n_pass = run_pytest(code, task)      # test pass rate
    return 0.3 if n_pass == 0 else (0.3 + 0.7 * n_pass / total_tests)
```
~20 lines. No other changes. Run 2 cycles with SCALING_FORCE_BOTH=1.

**Expected outcome**: all_fail tasks per cycle drops from 10-13 to <7 (target: <10% zero-adv
from all_fail group). Cycle-0 GRPO pass@1 improves 2-4pp vs binary-reward baseline. Provides
a new "3-tier reward" row in Table 9/10 and strengthens the Dark Room narrative with a
root-cause treatment alongside the algorithmic fix (EXP-135).
