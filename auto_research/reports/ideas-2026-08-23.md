### EXP-185 (Priority 8) — P2Skill: Prompt-Based Skill Distillation for Cloud-Local Routing Audit

**Paper:** arxiv:2608.14094 "P2Skill: Privacy Preserving Skill Distillation for Cloud-Local LLM Inference Systems"

**Key finding:** A local small model follows skill prompts to decompose tasks, route PII-sensitive components to the local model, and reconstruct responses — achieving near-cloud quality with privacy. The skill prompt format is a direct analog to MERA's `f"{procedure}\n\n---\n\n{problem}"` injection.

**Relevance to MERA:** MERA's SkillBook stores a single global `coding` procedure that is prepended to the small model's prompt. P2Skill validates this direction: skill prompts as routing + quality lever. The audit experiment: (1) compare P2Skill's decompose-paraphrase-reconstruct skill prompt schema vs. MERA's current single-procedure prefix on HumanEval held-out tasks; (2) measure whether structured multi-step skill prompts improve pass@1 vs. single procedure prefix on hard tasks (small model fails under current procedure). Offline analysis, no GPU.

### EXP-186 (Priority 7) — CVPO Value-Variance Advantage Adjustment for MERA GRPO

**Paper:** arxiv:2608.03068 "CVPO: Enhancing LLM Reinforcement Learning Reasoning via Value-Variance Adaptation and Dynamic Curriculum Learning"

**Key finding:** CVPO adds a value-variance term to the GRPO advantage estimate and uses dynamic curriculum weighting by problem difficulty. Value-variance at the token level correlates with exploration intensity and bounds policy update magnitude. On reasoning benchmarks, CVPO outperforms correctness-only GRPO.

**Relevance to MERA:** MERA's GRPO run (Phase 3b) has ACR=52.4% zero-variance groups (known issue, filed in EXP-184 via latent credit). CVPO provides a complementary approach: variance-aware advantage scaling that naturally upweights uncertain token positions and skips trivial problems via curriculum. Experiment: implement CVPO's variance-aware advantage as a drop-in patch to `src/pipeline/grpo_train_simple.py`, run on HumanEval with `GRPO_BATCH_SIZE=1`, compare pass@1 vs. standard GRPO baseline. GPU required.
