## Top 3 Relevant Papers

### 1. arxiv:2609.11446 — Calibration-Aware Uncertainty Cascades for Efficient Heterogeneous Model Collaboration (Sep 10, 2026)

**Authors**: Yilin Zhang, Han Jiang, Cai Xu, Ying Liu, Wei Zhao

**Core idea**: CAUC is a post-hoc framework that independently calibrates each model's confidence and selects cascade deployment thresholds using a common reliability scale derived from validation data. Unlike trained routers, CAUC requires no oracle label collection — confidence calibration (e.g., temperature scaling, isotonic regression) establishes a universal threshold language across heterogeneous models, so easy requests are served by the small model and hard ones escalate. The framework decouples routing policy from any particular model pool or cost budget.

**MERA intersection**: MERA's router is a *trained* model (logistic regression on raw prompt features, oracle labels from binary pass/fail runs). CAUC is the post-hoc counterpart: no training, no oracle labels, just calibrated confidence. The key MERA advantages over CAUC:
1. **Prompt-structural features**: MERA's router captures problem complexity cues that raw model confidence misses, especially at cycle 0 before the student is specialized.
2. **Co-evolution**: MERA re-trains the router each cycle as the student improves; CAUC's thresholds are static and do not adapt to a changing small model.
3. **Oracle label quality**: MERA's binary labels (small_pass/small_fail) are exact for HumanEval's pytest-graded problems; confidence calibration approximates this with noisy model logits.

Together with SRR (EXP-212, arxiv:2609.07786), CAUC and SRR define the no-training (CAUC) and Bayes-optimal-signal (SRR) ends of the cascade-routing spectrum. MERA sits at the trained + co-evolving end — a distinct point not covered by either paper.

**Paper impact**: §2 LLM Routing needs both Sep 2026 cascade papers; §4.2 gains a one-sentence comparison to CAUC's post-hoc approach.

### 2. arxiv:2609.07255 — SkillAlign: Aligning Skill Interfaces for LLM-based Agents (Sep 2026, EMNLP 2026)

**Authors**: Shuo Ren, Xiaomian Kang, Jiajun Zhang

**Core idea**: The same skill can help, distract, or mislead depending on how it is *exposed* to the agent. SkillAlign evaluates five exposure interfaces (full instructions, hints, compressed summaries, workflows, no exposure) across the same skill pool, holding agent backbone and tasks fixed. On ALFWorld, the optimal interface (full instructions with structured workflow) achieves 72.1% success vs. 47.9% for no-exposure — a 24.2pp gap driven purely by interface selection, not skill quality. SkillAlign is accepted to EMNLP 2026 main.

**MERA intersection**: MERA's procedure format (`f"{procedure}\n\n---\n\n{problem}"`) is a fixed "full instructions" exposure interface, hardcoded across SFT/GRPO/inference (Design Decision #4 in CLAUDE.md) for train/inference consistency. SkillAlign quantifies what MERA leaves on the table: up to ~24pp could be gained or lost by varying the interface. MERA does not explore this axis — the constraint is principled (a changed interface creates a train/inference mismatch), but SkillAlign gives it a concrete empirical stake.

**Paper impact**: §3 SkillBook gains an EMNLP 2026 citation that transforms Design Decision #4 from an implicit constraint into an acknowledged, quantified limitation.

### 3. arxiv:2603.16158 — Execution-Grounded Credit Assignment for GRPO in Code Generation (Mar 2026, ICLR 2026 Workshop SPOT)

**Authors**: Abhijit Kumar, Natalya Kumar, Shikhar Gupta

**Core idea**: GRPO-style updates suffer from coarse credit assignment — a single binary pass/fail outcome is spread uniformly over long program tokens. EGCA localizes advantage by comparing execution traces of the candidate and the canonical solution, identifying the earliest semantic divergence, and masking downstream tokens. Achieves 82.1% HumanEval pass@1 (+3.1 over GRPO), 68.9% MBPP (+1.5), 18% wall-clock overhead.

**MERA intersection**: MERA's Phase 3b GRPO uses pytest-graded binary rewards — exactly the coarse outcome signal EGCA addresses. If EGCA is not yet in §3 GRPO / §7 Remedies, it is an ICLR reviewer risk given it is an ICLR 2026 Workshop paper in exactly this setup. *Not queued today* (need to verify whether arxiv:2603.16158 is already in paper v13 before spending an experiment slot on it; lower risk than the two Sep 2026 papers queued today).
